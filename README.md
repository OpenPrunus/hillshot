# Hillshot

A turn-based artillery duel for the browser, inspired by the 1989 Macintosh shareware *Artillery* (System 7 look included).
Two castles face each other across a random hill. Set the **angle** of your cannon (0–90°) and the **powder charge**
(0–400 g), fire, and read the trace of your shell to correct the next shot. The wind changes every round and is never shown as a
number: watch the red flag. Play against the computer, with a friend on the same screen, or **online** (lobby, quick match,
challenges, Elo leaderboard). French and English, keyboard, mouse and touch.

## Features

- **Against the computer** in three levels. It solves the ballistics with the game's own engine, misjudges the wind and adds an
  error margin according to the level, then refines its powder charge by bisection from the miss of its previous shots.
- **Two players on one screen**, taking turns on the same board.
- **Online multiplayer**: a central PHP 8.5 server draws each round (hill, castles, wind), receives the setting of the player whose
  turn it is, computes the flight with the same engine as the browser and broadcasts it. Turn timer (an expired turn fires the
  last setting, two in a row forfeit), rematch, ping display.
- **Ranked matches** with an Elo rating, without any account: each browser has a secret token (only its SHA-256 hash is stored)
  that reserves the nickname. Anti-collusion: gains shrink when the same two players meet again within 24 hours.
- Two destruction rules: **classic** (one hit destroys a castle) or **health** (three hits).
- Persistent shell traces, procedurally generated terrain, castles placed at random on their plateaux, wind that changes every round.
- Pixel-art rendering on two canvas layers, held-down arrows that repeat (every 80 ms, then 25 ms), mouse wheel on the counters,
  sounds synthesized with the Web Audio API (no audio files).

## Quick start

```bash
git clone <this repository> hillshot
cd hillshot
docker compose up -d --build
```

Game: <http://localhost:8092> — game server: `ws://localhost:8093`. See [INSTALL.md](INSTALL.md) for a setup without Docker,
the configuration variables and a reverse-proxy example.

## Controls

| | |
| --- | --- |
| Angle | ↑ ↓ or **W S**, mouse wheel or the arrows on the counter (hold to repeat) |
| Powder | → ← or **D A**, mouse wheel or the arrows on the counter (**Shift**: steps of 5 and 10) |
| Fire | **Space** or **Enter**, or the *Fire* button |

On a phone the counters are touch buttons. The menu bar (File, Options, Help) offers new games, the player names, the
destruction rule, sound and language.

## Architecture

```
web/                 the website, served by Apache (document root)
  index.php          single page (Macintosh window, menus, board); injects the WebSocket URL (HILLSHOT_WS)
  js/engine.js       the game: terrain, ballistics, duel (pure and deterministic)
  js/ai.js           the computer opponent (seeded random generator: a game is replayable)
  js/render.js       pixel-art scene on two canvas layers (background with the traces, animated layer)
  js/main.js         menus, turns, shot settings, shell animation, local and online modes
  js/net.js          WebSocket client       js/audio.js  synthesized sounds       js/i18n.js  FR / EN
  api.php            leaderboard (GET), reads the file written by the game server
src/                 all PHP code, PSR-4 namespace `Hillshot\` (see below)
server/              entry point of the game server (a few lines of wiring), outside the web root
tests/               JS unit tests, PHP unit tests, integration tests, browser tests
```

### The engine exists twice, and tests keep both identical

The browser needs the engine for the computer and the same-screen modes; the server needs it to referee online matches.
`web/js/engine.js` and `src/Engine/` are therefore two implementations of the same rules. `tests/fixtures/engine-vectors.json`
(generated by `npm run fixtures`) records matches played by the JavaScript engine — rounds, shots, full flight paths, damage, scores —
and `tests/php/Engine/FixturesTest.php` replays them with the PHP engine and requires the same results (tolerance 1e-9).
The integration tests also compare the flight sent by the real PHP server with the JavaScript flight, point by point.

Physics: the initial speed is proportional to the powder (calibrated so that 400 g at 45° with no wind covers 680 px), constant gravity,
a horizontal wind acceleration, fixed steps of 1/60 s. The ground is a plateau plus a Gaussian hill,
`y(x) = base − H·exp(−(x−xc)² / 2σ²)`.

### PHP code (`src/`)

PHP 8.5, PSR-4 autoloading, PSR-12 style, `declare(strict_types=1)` everywhere, PHPStan level 8. Runtime dependencies are the PSR
interfaces `psr/log` (PSR-3) and `psr/clock` (PSR-20), and [`openprunus/arcade-core`](https://github.com/OpenPrunus/arcade-core),
the WebSocket server and support classes shared with Chicken Challenge and Gloop Volley (namespace `Arcade\`).

| Namespace | Role | Patterns |
| --- | --- | --- |
| `Hillshot\Engine` | The game: `Duel`, `Round`, `RoundFactory`, `Ballistics`, `Shot`, `Trajectory`, `Outcome`, enums `Side` / `Mode` / `Fate` | Value objects, **Factory** (`RoundFactory`) |
| `Hillshot\Game` | The multiplayer server: `GameHub` (facade), `Lobby`, `Invitations`, `MatchQueue`, `MatchService`, `Room`, `RankingBook` | **Command** (one `Handler\*` per client message), **Factory** (`GameHub::create`), **State** (`RoomPhase`) |
| `Hillshot\Ranking` | `Elo`, `Ranking` (immutable), `Player`, `PairLimiter`, `RankingStore` | **Repository** (`RankingStore`), immutable objects updated with `clone with` |
| `Hillshot\Api` | `Board`: the public leaderboard | |
| `Arcade\WebSocket`, `Arcade\Server` *(arcade-core)* | RFC 6455 codec and the `stream_select` server; it knows nothing about the game | **Adapter** (`Connection` implements `Transport`); the game plugs in through `Hub` (`GameHub`) and `Session` (`Client`) |
| `Arcade\Support` *(arcade-core)* | `Env`, `Nickname`, `SystemClock` (PSR-20), `StdoutLogger` (PSR-3), `AtomicFile` | Dependency injection of clock, logger and randomizer |

PHP 8.5 features in use: `clone with` on readonly classes (`Player`), `#[\NoDiscard]` (`Ranking::record`), `array_find` / `array_last`,
property hooks and asymmetric visibility (`Duel`, `Client`, `RankingBook`), typed class constants, enums, `readonly` classes,
`#[\Override]`, `json_validate` and `Random\Randomizer` injection.

### How online play works

- The browser opens a WebSocket, sends `hello` (nickname + token) and joins the lobby. `queue` starts a quick match, `challenge`
  invites a player.
- The server announces each **round** (`round`: hill, castle positions, wind, who starts, health, score), then the player whose turn it
  is sends `fire` (angle, powder). The server computes the flight and sends `shot` (full path, fate, health, score) to both players.
  Once the shell has been animated, it sends `turn` (the other player) or `round` (the next round) or `result`.
- Every setting is clamped to its bounds server-side; a player cannot fire out of turn, and the server never trusts the client for
  damage or score. Origin check on the WebSocket, 60 messages per second per client, 2 KB per message.

## Tests

```bash
composer install && composer check   # PSR-12, PHPStan level 8, PHPUnit (incl. replay of the JS engine's matches)
npm run test:unit         # engine, AI, translations
npm run test:integration  # the real PHP server on a real port, WebSocket clients
npm run test:browser      # headless Chrome: menus, held arrows, shells and traces, phone layouts, an online match against a bot
```

CI runs all of it and a smoke test of the Docker image on every push.
